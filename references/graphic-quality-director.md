# 그래픽 품질 디렉터

영상(또는 스타일 데모) 하나를 만들기 전에 **6분야를 결정하고**, 만든 뒤 **실제 렌더링 화면으로 검증**하는 규칙.
핵심 원칙: **효과는 고르는 것이지 전부 켜는 것이 아니다.** 스타일과 장면에 맞는 기술만 적용한다.

> 출처 구분: 이 문서의 항목 체계(LOOK / CAMERA / MOTION / RENDERING / QUALITY CONTROL)는 사용자가 제작 지시서에 적어 준
> 분석 항목을 그대로 따른다. 지시서가 언급한 '클로드 모션그래픽 프롬프트' 원문 파일(Ctrl+C/V 캐릭터 루프, 랜딩페이지 3D
> 플라이오버, 제품 런칭 영상)은 제작 당시 이 PC에서 찾지 못했다. 따라서 아래 구체 수치와 적용 규칙은 **원문 인용이 아니라
> 이 스킬에서 새로 설계한 것**이며, 8종 데모를 실제로 만들고 검증하면서 확인한 값이다. 원문을 구하면 §8에 따라 보강한다.

## 0. 쓰는 순서
1. 스타일 확정 → `styles/<id>/style.json` 의 `quality` 와 `notes.md` 를 읽는다(그 스타일의 기본 결정).
2. 이번 영상의 장면별로 아래 A~E 를 한 줄씩 적는다(**품질 시트**, §7 양식). 기본 결정에서 바꾸는 항목만 이유와 함께.
3. 구현한다.
4. F(시각 QA)를 실제 프레임으로 수행한다. 통과 못 하면 고치고 다시 캡처한다.

## 1. A. Art Direction
| 결정 | 기준 |
|---|---|
| 팔레트 | 주조 1 + 보조 2~3 + 강조 1 + 중성 1~2. 강조색은 화면의 5~10%만. 스타일 데모의 팔레트 상수를 출발점으로 주제에 맞게 색상만 교체하고 명도·채도 구조는 유지 |
| 형태 언어 | 한 영상에 하나(각진/둥근/손그림/기하). 섞지 않는다 |
| 화면 밀도 | 주 피사체 주변 30%는 비우고, 나머지는 2차 디테일로 채운다. 1920×1080에서 "빈 색면이 화면의 1/4 이상"이면 밀도 부족 |
| 전경·중경·배경 | 3겹을 명도/채도/선명도로 구분. 배경은 주제보다 대비를 낮춘다 |
| 시각적 초점 | 장면마다 1개. 가장 높은 대비 + 가장 큰 움직임을 초점에만 준다 |
| 분위기 | 시간대·날씨·색온도를 한 문장으로 적는다 ("맑은 오전, 따뜻한 주광") |

## 2. B. Material Direction
| 스타일 계열 | 재질 결정 |
|---|---|
| 3D 사실/반사실(02, 06) | 재질군별 roughness 를 다르게(같은 값이면 플라스틱 장난감처럼 보인다). 절차적 텍스처로 미세 색변화·bump. 텍스처는 mipmap + anisotropy 최대. 물/유리만 낮은 roughness |
| 3D 무광(01) | 텍스처 없음. 면 방향별 밝기 차이로 구조를 읽힌다 |
| 2D 회화(03, 05) | 고정 시드 노이즈로 종이결·붓자국. 로드 시 한 번 생성해 캐시. 조각마다 명도 미세 편차 |
| 2D 그래픽(04, 07) | 재질 없음. 단색 면. 윤곽선 두께 전부 통일 |
| UI 유리(08) | 실제 `backdrop-filter`. 틴트 알파 0.10~0.18, 1px 그라데이션 테두리, 안쪽 상단 반사 |

단순화 수준은 스타일이 정한다. **한 화면에 서로 다른 단순화 수준을 섞지 않는다**(로폴리 집 옆에 사실적 나무 금지).

## 3. C. Lighting Direction
- 주광 1개의 방향을 정하고 **모든 그림자·하이라이트가 그 방향을 따른다**(2D 스타일도 동일: 드롭섀도 오프셋, 칠한 그늘).
- 색온도 대비: 따뜻한 주광 + 차가운 보조/환경광(또는 반대). 같은 색온도 두 개는 평평해 보인다.
- 접촉 그림자: 바닥에 닿는 모든 물체에 필요. 없으면 떠 보인다. 3D는 PCFSoft 그림자 맵 2048 이상 + 그림자 카메라를 장면에 맞게 좁힌다(해상도 낭비 방지). bias/normalBias 로 아크네 제거.
- 그림자 부드러움: 야외 맑음=선명, 스튜디오/흐림=넓은 반그림자. 디오라마는 부드럽게.
- 강조 조명: 초점 피사체에만 림라이트나 밝기 +10~15%.
- 대기 원근: 넓은 공간(02, 03)에만. 멀수록 밝고 푸르고 대비가 낮게. 탁상 모형(06)·아이소(01)·그래픽(04, 07)에는 쓰지 않는다.

## 4. D. Camera Direction
| 결정 | 기준 |
|---|---|
| 투영 | 아이소=정사영 고정각. 넓은 풍경=원근 FOV 30~40. 미니어처=망원 FOV 20~28(원근 압축). 2D=투영 없음, 레이어 패럴랙스 |
| 높이·거리 | 주 피사체가 화면 높이의 35~60%. 지평선은 1/3 선 근처 |
| 이동 경로 | 장면당 이동 1개(push-in, 궤도 호, 팬, 크레인 중 하나). 경로는 스플라인/삼각함수로 연속. 두 장면 사이에서 위치·속도가 이어지게 |
| 속도 곡선 | 시작·끝 모두 ease(정지에서 출발해 정지로). 일정 속도는 드론 플라이오버처럼 "계속 가는" 경우만. 루프 영상은 닫힌 경로 |
| 피사계 심도 | 미니어처·제품 클로즈업에만. 초점 대상을 명시하고 초점 거리를 매 프레임 카메라-대상 거리로 계산 |
| 구도 안정성 | 이동 중에도 초점 피사체가 안전 영역(가장자리 8% 안쪽) 밖으로 나가지 않는다. 텍스트는 가장자리 5% 안쪽 |

카메라 튐 방지: 카메라 위치를 `t` 의 연속 함수 하나로 만든다. 장면별로 따로 트윈을 걸어 이어 붙이지 않는다.

## 5. Motion (MOTION 항목)
- **Anticipation → Action → Overshoot → Settle**: 캐릭터·오브젝트의 "의지 있는" 움직임에 적용. 반대 방향 예비 동작 8~15%, 목표 초과 5~12%, 1~2회 감쇠 후 정착. 플랫 벡터·카툰에서 가장 효과가 크고, 디오라마·사실적 3D에서는 약하게.
- **Secondary motion**: 주 동작보다 80~200ms 늦게 따라오는 부속물(잎, 깃발, 연기, 머리카락).
- **가감속**: 선형 이동 금지(일정 유속의 물·컨베이어 등 물리적으로 등속인 것만 예외).
- **루프 연속성**: 모든 주기를 영상 길이의 정수 분할로. 이음매에서 위치뿐 아니라 **속도**도 이어져야 한다. `validate-demo.js` 의 루프 이음매 검사로 확인.
- **스톱모션 느낌**(05): `t` 를 1/12초로 양자화. 그 외 스타일은 양자화하지 않는다.
- 구현 규칙: 화면 상태는 `render(t)` 의 **순수 함수**. 그래야 임의 프레임 추출·오프라인 렌더·결정적 재현이 된다.

**실시간 HTML vs MP4 오프라인** (자세한 설정은 `rendering-guidelines.md`)
- 실시간: 60fps 유지가 우선. DPR ≤ 2, 그림자 맵 2048, 후처리 패스 최대 2개, 모션블러 없음.
- 오프라인(MP4): 프레임당 시간이 자유롭다. 그림자 맵 4096, 서브프레임 누적 모션블러(프레임당 4~8 샘플, 빠른 카메라 이동이 있을 때만), 2배 슈퍼샘플링(`--scale 2`) 가능.
- 고비용 효과(DOF, 블룸, 모션블러, SSAO)는 "켜기 전/후 프레임을 나란히 봤을 때 차이가 분명할 때만" 유지한다.

## 7. F. Visual Quality Assurance
**코드가 오류 없이 실행된다는 것은 통과 조건이 아니다.** 반드시 실제 프레임을 본다.

절차
1. `node scripts/validate-demo.js --url <영상 주소> --duration <초>` → 로드·콘솔 오류·결정성·루프·깜빡임 자동 검사.
2. `node scripts/create-contact-sheet.js --url <영상 주소> --duration <초>` → 6프레임 Contact Sheet. **에이전트의 이미지 보기 기능으로 PNG 를 직접 열어 본다.**
3. 아래 체크리스트를 프레임별로 판정하고, 실패 항목을 고친 뒤 1~2를 다시 한다. 최소 1회는 수정 후 재캡처로 개선을 확인한다.

체크리스트
- [ ] 스타일 일관성: 선택한 스타일 데모(`styles/<id>/preview.png`)와 나란히 놓았을 때 같은 계열로 보이는가
- [ ] 색상 조화: 팔레트 밖의 튀는 색이 없는가, 강조색이 초점에만 쓰였는가
- [ ] 재질 완성도: 플라스틱처럼 균일하지 않은가(3D), 질감이 타일링되어 보이지 않는가
- [ ] 그림자: 접촉 그림자 존재, 방향 일치, 아크네·피터패닝(그림자가 물체에서 떨어짐) 없음
- [ ] 카메라 구도: 초점 피사체가 안전 영역 안, 지평선 기울지 않음, 어색하게 잘린 물체 없음
- [ ] 겹침·관통: 물체가 서로 또는 지면을 뚫지 않는가, 떠 있지 않은가
- [ ] 깜빡임: z-fighting, 그림자 떨림, 한 프레임만 튀는 값(자동 검사 경고 확인)
- [ ] 애니메이션 연속성: 인접 프레임 간 순간이동 없음, 루프 이음매(루프 영상)
- [ ] **내용 정확성(교과·사실)** — 묘사한 과정이 실제 또는 교과서와 일치하는가. 바늘은 바늘끝부터 나오고 끝이 이동 방향을 향하는가, 박음질의 땀은 눈으로 구분되는가, 번호·라벨은 동작 순서와 맞는가.
- [ ] 텍스트 가독성: 1920 기준 최소 22px, 배경 대비 충분, 잘림·겹침 없음, 1280×720 축소 시에도 판독
- [ ] 시작과 끝: 첫 프레임이 빈 화면이 아니고, 마지막이 갑자기 끊기지 않는다(루프면 이음매, 아니면 정착 후 0.5초 유지)
- [ ] 의도 비교: 품질 시트에 적은 결정(조명 방향, 초점 대상, 카메라 경로)이 실제 화면에 그대로 보이는가

## 품질 시트 양식 (장면마다 5줄)
```
장면 N (0.0–4.0s) — <한 줄 내용>
Art:      팔레트/초점/밀도
Material: 재질군과 단순화 수준
Light:    주광 방향·색온도, 그림자 성격
Camera:   투영/FOV, 경로, 속도 곡선, 초점 대상
Render:   켜는 효과와 끄는 효과(이유)
```

## 8. 원문 프롬프트로 보강할 때
'클로드 모션그래픽 프롬프트' 원문을 구하면: 예제별로 LOOK/CAMERA/MOTION/RENDERING/QC 지시를 뽑아 이 문서 해당 절에 `[원문: 예제명]` 표시와 함께 추가하고, §6 적용표에 어느 스타일에 해당하는지 표시한다. 모든 스타일에 일괄 적용하지 않는다.
