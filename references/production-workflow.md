# 제작 워크플로

## STEP 1. 요청

주제와 목적, 스타일, 길이·비율·fps, 설명 방식을 읽는다. 필요한 질문만 **한 메시지**에 묶고, 나머지는 15초·16:9·30fps와 [소리 가이드](sound-guide.md)의 목적별 기본값으로 진행한다.

| 사용자 말 | 동작 |
|---|---|
| 스타일을 지정함 | `style-catalog.md`의 별칭 표로 스타일을 정한다. |
| 스타일을 맡김 | 주제→스타일 선택표에서 골라 이유를 한 줄로 알린다. |
| 스타일 언급 없음 | 갤러리에서 8종 고정 데모를 보여 주고 선택을 받는다. |

- 갤러리는 `node <스킬>/scripts/serve.js --open --clear`로 연다. 번호(1~8)를 말하거나 **이 스타일로 선택** 버튼을 누르도록 안내한다. “골랐어”라고 하면 OS 임시 폴더의 `bangmotion-visual-director/selection.json`을 읽고 선택이 끝나면 갤러리 서버를 종료한다.
- 수업·설명 영상에서 설명 방식이 비어 있으면 갤러리 안내와 같은 메시지에서 묻는다. “① 음악·효과음만(화면 글자로 설명, 기본값) ② 내레이션 ③ 소리 없음”. 스타일이 이미 정해졌거나 선택을 맡겼으면 별도 요청이 없는 경우 기본값으로 진행한다.
- 갤러리를 열 수 없으면 `style-catalog.md`의 표에서 번호를 받는다. 기본값과 보여 주지 못한 데모는 보고에 적는다.

## STEP 2. 설계서

- 프로젝트 폴더에 설계서 한 장을 쓴다. 길이·비율·fps, 스타일과 선정 이유, 공간·카메라 방식, 장면표(번호·시작/끝·내용·카메라·동작·화면 문구), 장면별 품질 시트(Art·Material·Light·Camera·Render), 소리 큐 계획(시각·화면 사건·내용/스타일 소리·음악/내레이션)을 담는다.
- `styles/<id>/style.json`과 `notes.md`를 읽고 스타일과 맞는 연출기법 1~3개를 `bangmotion-directing-library.md`에서 고른다. 선택한 기법을 설계서에 적는다.
- `templates/scenes.json`을 본떠 프로젝트에 `scenes.json`을 쓴다. `fps`·`aspect`와 각 장면의 `id`·`label`·`start`·`end`를 장면표와 맞춘다. 초안 장면 버튼과 소리 큐의 타이밍은 이 시각을 기준으로 잡는다.

## STEP 3. 구현 → 자동 검사 + 눈으로 확인

선택한 스타일의 팔레트, 재질·조명·카메라 설정, 그리기 헬퍼를 새 구도와 오브젝트에 적용한다. 프로젝트에 `index.html`, JS, `shared/runtime.js`, 필요한 `vendor/three`를 넣고 `render(t)`의 순수 함수 계약을 지킨다. 한 세계 안에서 카메라와 오브젝트의 움직임으로 장면을 연결한다. 화면 문구는 한국어로 쓰고 큰 문장과 라벨까지 두 단계로 제한한다.

```
node <스킬>/scripts/validate-demo.js --url <프로젝트>/index.html --duration <초> [--no-loop]
node <스킬>/scripts/create-contact-sheet.js --url <프로젝트>/index.html --duration <초>
```

Contact Sheet를 직접 열어 `graphic-quality-director.md` §7로 판정한다. **내용 정확성(교과·사실)**도 확인한다. 바늘이 바늘끝부터 나오며 끝이 이동 방향을 향하는지, 박음질의 땀들이 눈으로 구분되는지, 번호·라벨이 동작 순서와 맞는지 본다. 전환이나 중요한 동작은 `--times`로 프레임을 추가한다. 문제가 있으면 고치고 다시 캡처한다.

## STEP 4. 소리 1차

`templates/sound.json`을 바탕으로 영상 길이와 장면표에 맞춰 프로젝트의 `sound.json`을 쓴다. ffmpeg가 있으면 `node <스킬>/scripts/sound.js <프로젝트>`로 초안 믹스를 만들고 통합 음량·실제 피크·모노와 파형의 큐 위치를 확인한다. 출처·라이선스를 확인하고, 무음 요청은 `mode: "none"`으로 기록한다.

## STEP 5. HTML 초안

`node <스킬>/scripts/bundle-preview.js <프로젝트>`로 소리를 포함한 `preview.html`을 만들어 전달한다. 사용자는 Chrome 또는 Edge에서 더블클릭해 연다.

- 장면 번호·이름·시간을 안내한다. 예를 들어 “1. 도입 0–8초 · 2. 과정 8–17초”.
- Space 재생·정지, ←/→ 한 프레임, Shift+←/→ 0.5초, Home 처음, 스크럽 막대, 1~9 장면 반복, 반복 토글, 0.25×·0.5×·1×, M 소리, C 시각 복사, R 현재 위치에서 다시 읽기를 안내한다.
- 바꿀 내용을 말로 알려 달라고 한다. 복사한 시각과 프레임을 그대로 붙여도 된다.

## STEP 6. 말로 수정 반복

요청한 장면과 시간만 바꾸고 확정된 장면은 그대로 둔다. `validate-demo.js`를 다시 실행하고 `create-contact-sheet.js --times <쉼표로 구분한 시각>`으로 해당 구간을 뽑아 눈으로 전후를 비교한다. 타이밍이 바뀌면 `scenes.json`과 큐를 맞춘다. `preview.html`을 재생성하고 R로 다시 읽도록 안내한다. 수정 시각·내용·확정 여부는 같은 설계서에 기록한다.

## STEP 7. 확정 후 상영과 영상 저장

확정된 `preview.html`로 바로 상영한다. 영상 파일이 필요하면 **● 영상으로 저장**에서 이 탭과 탭 오디오를 공유해 실시간으로 녹화한다. 녹화가 끊기거나 프레임이 정확한 고품질 MP4가 필요할 때는 `render-demo.js`로 MP4와 썸네일을 만든다.

```
node <스킬>/scripts/render-demo.js --url <프로젝트>/index.html --out <프로젝트>/out/video.mp4 --thumbnail <대표 시각>
```

내보낸 MP4의 통합 음량·실제 피크·모노를 다시 재고 `out/sound/final-<영상 이름>.json`의 `issues`를 확인한다. 주요 소리 큐 몇 곳에서 MP4 프레임을 직접 뽑아 동작과 시각을 대조한다.

## STEP 8. 보고

첫 줄은 “preview.html 더블클릭 → ⛶ 상영(F) / ● 영상으로 저장”으로 시작한다. 결과물 경로, 쓴 스타일과 연출기법, 고친 점과 미검증 항목, 적용한 기본값을 적는다. 소리가 있으면 측정한 LUFS·실제 피크, 출처·라이선스, 사람이 헤드폰으로 확인할 시각 다섯 곳을 함께 적는다.
