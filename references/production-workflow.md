# 제작 워크플로

요청 한 건을 받아 완성 영상까지 가는 절차. 사용자가 중간 승인을 요구하지 않았다면 STEP 2~5 는 묻지 않고 진행한다.

## STEP 0. 요청 읽기
확인할 것: 주제, 목적(수업 도입/개념 설명/홍보…), 길이, 화면 비율, 스타일 지정 여부, 출력 형식.
빠진 값의 기본값: 길이 15초, 16:9, 30fps, 출력 = HTML + (ffmpeg 있으면) MP4 + 썸네일. 기본값을 썼으면 보고에 적는다. 주제가 없을 때만 되묻는다.

## STEP 1. 스타일 결정 — 세 갈래
| 사용자 말 | 동작 |
|---|---|
| 스타일을 지정함 ("아이소메트릭으로", "종이 오린 느낌", "3번") | 갤러리를 띄우지 않는다. `style-catalog.md` 의 별칭 표로 id 를 정하고 바로 STEP 2 |
| 스타일을 맡김 ("알아서", "추천해 줘") | `style-catalog.md` 의 주제→스타일 선택표로 1개를 고르고, 고른 이유를 한 줄로 알린 뒤 진행 |
| 스타일 언급 없음 | 갤러리를 보여 주고 선택을 받는다(아래) |

갤러리 띄우기
1. `node <스킬>/scripts/serve.js --open --clear` 를 **백그라운드**로 실행한다(출력 첫 줄의 주소 확인). 백그라운드 실행을 못 하는 에이전트는 이 명령을 사용자에게 주고 별도 터미널에서 실행해 달라고 한다.
2. 사용자에게 안내: "브라우저에 스타일 8종 갤러리를 열었습니다. 카드를 눌러 5초 데모를 보고 **이 스타일로 선택**을 누르거나, 번호(1~8)를 여기에 말해 주세요."
3. 선택 확인 방법(둘 중 먼저 오는 것):
   - 사용자가 대화에 번호/이름/복사된 문구(`스타일 선택: 03-storybook-2p5d`)를 말한다.
   - 사용자가 "골랐어"라고만 하면 `<OS 임시폴더>/bangmotion-visual-director/selection.json` 을 읽는다(서버 터미널 출력의 `[선택됨] …` 줄과 같다). 경로는 `node -e "console.log(require('os').tmpdir())"` 로 확인.
4. 선택을 받으면 서버를 종료한다. 브라우저를 띄울 수 없는 환경이면 `style-catalog.md` 의 표를 대화에 보여 주고 번호로 받는다(이때는 "실제 데모를 못 보여 드렸다"고 알린다).

갤러리의 데모는 고정이다. **새 주제에 맞춰 데모를 다시 만들지 않는다.**

## STEP 2. 연출 설계
1. `styles/<id>/style.json` (`axes.fits_techniques`, `quality`) 과 `styles/<id>/notes.md` 를 읽는다.
2. `bangmotion-directing-library.md` 의 빠른 선택표에서 목적에 맞는 연출기법 1~3개를 고른다. 내용 전달이 기준이다 — 화려함이 목적이 아니다.
3. 스타일과 충돌하는 기법은 뺀다(예: 플랫 벡터에 시네마틱 DOF 플라이오버, 아이소메트릭에 카메라 회전 궤도).
4. `templates/` 에서 목적에 맞는 뼈대를 골라 장면 수와 시간 배분을 잡는다.

## STEP 3. 제작 설계서 (대화에 짧게 보여 주고 바로 진행)
```
길이 / 비율 / fps:
그래픽 스타일:        <id> — 이유
공간·카메라 방식:
핵심 연출기법:        1) … 2) …
장면표:               N. 0.0–4.0s  내용 / 카메라 / 주요 애니메이션 / 화면 속 텍스트
품질 시트:            장면별 Art·Material·Light·Camera·Render (graphic-quality-director.md 양식)
출력:                 HTML / MP4 / 썸네일
```

## STEP 4. 구현
- 프로젝트 폴더(사용자 작업 폴더 아래 `<주제-슬러그>/`)에 `index.html` + JS. 스킬의 `shared/runtime.js` 와 필요한 `vendor/three` 를 복사해 넣는다(스킬 폴더를 직접 참조하지 않는다 — 결과물이 혼자 실행돼야 한다).
- 선택한 스타일의 `demo.js` 에서 **팔레트 상수, 재질·조명·카메라 설정, 질감 생성 함수, 그리기 헬퍼**를 가져다 쓴다. `notes.md` 에 재사용할 함수 이름이 적혀 있다.
- **데모의 장면(강·다리·집)을 복제하지 않는다.** 새 주제에 맞는 오브젝트와 구도를 새로 만든다. 가져오는 것은 미술 규칙과 구현 방식이다.
- 여러 장면이 있는 영상은 bang-motion 의 anti-PPT 원칙을 지킨다: 장면을 fade 로 갈아 끼우지 말고 하나의 세계 안에서 카메라/오브젝트가 움직여 다음 내용으로 넘어간다(`bangmotion-directing-library.md` 개요).
- 화면 속 텍스트는 한국어, 장면당 2단계 이내(큰 문장 1 + 라벨).
- 사용자 환경에 코딩 위임 규칙(다른 에이전트·워커에게 구현을 맡기는 규칙)이 있으면 그 규칙을 따른다. 위임할 때 지시문에 스타일 notes.md 경로, 재생 계약, 품질 시트, 완료 조건을 넣는다.

## STEP 5. 시각적 검증 (생략 금지)
```
node <스킬>/scripts/validate-demo.js --url <프로젝트>/index.html --duration <초> [--no-loop]
node <스킬>/scripts/create-contact-sheet.js --url <프로젝트>/index.html --duration <초>
```
Contact Sheet 이미지를 직접 열어 보고 `graphic-quality-director.md` §7 체크리스트로 판정한다. 문제를 고치고 다시 캡처해 개선을 확인한다. 20초 이상 영상은 장면 전환 시점의 프레임을 `--times` 로 추가 지정한다.

## STEP 6. 최종 출력
- HTML: 프로젝트 폴더 그대로.
- MP4 + 썸네일: `node <스킬>/scripts/render-demo.js --url … --out <프로젝트>/out/<이름>.mp4 --thumbnail <대표 시각>`.
- 보고: 결과물 경로, 사용한 스타일·연출기법, 검증에서 고친 것, 확인하지 못한 것(예: 실제 수업 프로젝터 색감).

## 기존 영상 수정 요청
1. 프로젝트의 `index.html` 을 읽고 현재 스타일 id·장면표를 파악한다(없으면 화면을 캡처해 판단).
2. 바꾸는 범위만 고친다. 스타일을 바꾸라는 요청이면 STEP 1 부터, 내용·타이밍만이면 STEP 3 부터.
3. 수정 후 STEP 5 를 다시 한다. 수정 전/후 Contact Sheet 를 비교해 의도하지 않은 변화가 없는지 본다.
