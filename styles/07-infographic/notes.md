# 인포그래픽 모션 재사용 안내

공간이나 구조를 보여 주면서 수치를 설명하는 5초 도해다. 수치는 가상의 예시이며, 첫 프레임부터 모든 정보가 보인다. 변경 범위는 이 폴더의 네 파일이며 공통 시계와 다른 스타일은 수정하지 않는다.

## 품질 디렉터 결정

- **Art**: `PALETTE`, `TYPE`, `buildScene()`에서 7색과 네 단계 글자를 관리한다. 1920 기준 제목 58px, 라벨 28px, 수치 36px, 캡션 24px다. 88px 왼쪽 정렬선, 221px 제목 구분선, 1456px 요약 열을 유지한다. 나무 7그루는 활엽수 4그루·침엽수 3그루로, 굽은 강 양쪽에 집 2채와 중앙 아치 다리를 둔다. 풀·돌·울타리·창틀·계단·강둑을 설명 대상보다 낮은 대비로 채운다.
- **Material**: `MATERIAL`, `tree()`, `house()`, `bridge()`가 재사용 가능한 평면 벡터 부품이다. 선과 단색 면을 쓰고 투명도만으로 멀리 있는 언덕을 구분한다. 빨간 지붕은 주황 계열의 적갈색, 파란 지붕은 팔레트의 청색 계열 남색으로 제한한다.
- **Lighting**: `LIGHTING`은 실사 조명이나 그림자를 사용하지 않는다. 지면과 맞닿은 줄기·집 기단·다리 교대에 접지선을 두고, 강둑에 중간 명도 윤곽을 넣는다. 강조는 빛 대신 주황 테두리·라벨 크기·대비로 전달한다.
- **Camera**: `CAMERA`, `render()`에서 2D 도해 전체를 최대 0.5% 확대하고 몇 px 이동한다. 코사인 곡선의 1회 왕복 줌과 순환 강조점 가중치가 닫힌 경로를 만든다. 제목과 범례도 함께 움직이므로 가장자리 80px 이상을 확보한다.
- **Rendering**: `index.html`의 SVG viewBox는 1920×1080이며 화면 비율에 맞춰 중앙 정렬한다. SVG 자체의 벡터 안티앨리어싱을 사용하며, Canvas의 DPR·WebGL·Three.js는 필요 없다. 시스템 글꼴만 사용한다. CSS animation/transition, 자체 재생 시계, 외부 리소스 요청은 없다.
- **QA**: `?t=0`, `?t=2.5`, `?t=4.9` 고정 프레임, 1280×720 축소, 5초 경계, 임의 시점 역방향 seek, 콘솔 오류, 외부 요청, 텍스트 경계를 확인한다. 동일 시점에 다시 seek한 SVG 속성이 같아야 한다. 가장 작은 24px 글자는 720p에서 16px다. 새 문구는 실제 시스템 글꼴로 폭을 측정해 치수선·주석과의 간격을 다시 점검한다.

## 새 주제로 바꾸는 순서

1. `buildScene()`의 제목·본문·범례와 요약 수치를 바꾼다. `text()`는 내부의 신뢰된 고정 문구용이며 사용자 입력은 반드시 이스케이프하거나 DOM의 `textContent`로 넣는다.
2. 장면을 교체할 때 `house()`, `tree()`, `bridge()`의 단색 도형 문법을 유지한다. SVG 레이어는 배경 → 지면·강 → 건물·다리·나무 → 지시선·치수 → 강조 순서다.
3. `targets`의 중심·타원 크기와 `label()`의 주석 좌표를 함께 조정한다. 집은 두 강조 타원으로 묶는다. 두 치수 모두 양끝 틱과 중앙 숫자를 유지한다. 강 폭 숫자 뒤의 종이색 바탕은 선을 가려 수치가 중앙에 읽히게 한다.
4. `emphasisAt(t)`가 다리 → 강 → 집 → 나무를 1.25초씩 읽는다. 각 구간 전반은 정지하고 후반은 smoothstep으로 다음 대상에 넘긴다. 마지막 나무에서 첫 다리로도 같은 곡선으로 연결한다.
5. `render(t)`의 물결·나무·구름·연기에는 5초의 정수 주기 함수만 쓴다. 점선 이동은 대시 패턴 21px의 정확히 3배인 63px를 한 루프에 이동시킨다. 누적 위치나 프레임 수를 사용하지 않는다.

## 사용하지 않는 효과

DOF, 3D 원근, 실사 텍스처·광원, 장식 그라데이션, 글로우, 입자 폭발, 화면 흔들림, 글자 모핑을 사용하지 않는다. 주석의 정보를 숨기는 등장 애니메이션이나 숫자 카운트업도 사용하지 않는다. 강조되지 않은 항목은 글자만 약간 흐려지며 풍경 전체의 읽힘은 유지한다.

## 실시간 재생과 MP4 오프라인 렌더링

- 실시간은 `start(render)`의 기본 자동 재생을 사용한다. 창 리사이즈는 CSS가 처리하며 SVG의 논리 좌표는 고정이다. 별도 해상도나 DPR 설정은 없다.
- 오프라인은 외부 캡처 도구에서 1920×1080, deviceScaleFactor 1, `?t=0`으로 열고 `window.__demoReady`와 `document.fonts.ready`를 기다린다. 프레임마다 `window.__demo.seek(frame / fps)` 후 캡처한다. 30fps라면 0~149 프레임만 저장하여 마지막 중복 프레임을 만들지 않는다.
- 1280×720 출력도 동일하게 viewport만 바꾼다. 폰트·색·선·카메라 설정은 바꾸지 않는다. MP4 인코딩은 외부 도구에서 H.264, yuv420p, 충분한 비트레이트를 쓰고 흐릿해지는 저비트레이트를 피한다. 이 데모에 인코더나 별도 시계를 넣지 않는다.
- 미리보기 이미지와 GIF는 공통 캡처 파이프라인이 생성한다. 이 폴더에 수동 스크린샷·시험 스크립트·인코딩 결과를 남기지 않는다.

## 본 구현의 확인 범위

헤드리스 Chrome에서 1920×1080의 0·2.5·4.9초 화면과 강·나무 강조 시점, 1280×720 축소 화면을 직접 확인하고 반복 개선했다. 30fps 기준 150프레임의 글자 겹침과 화면 경계 초과는 0건이다. 콘솔 오류·외부 요청도 0건이며 동일 시점 재호출의 SVG 일치, 자동 재생, 쿼리 고정, 정사각 창의 16:9 레터박스를 확인했다. 4.999초와 0초 캡처의 RGB 채널 평균 차이는 255 기준 0.04 미만이다. ES 모듈 문법과 공통 시계 import 경로를 확인했다. MP4 인코딩과 다른 운영체제의 시스템 글꼴 조합은 검증하지 않았다.
