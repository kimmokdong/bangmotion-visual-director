# 플랫 벡터 재사용 안내

## Art — 도형과 밀도

`demo.js` 상단 `PALETTE`의 6색과 흰색만 사용한다. 코랄은 왼쪽 지붕과 다리의 강조면, 남색은 오른쪽 파란 지붕·난간·나무의 구조, 청록은 강에 배정했다. 크림색 바탕과 초록 지면으로 배경·중경·전경을 구분한다. 위치·모서리·간격의 기본 단위는 8px이며 원과 삼각형, 둥근 사각형으로 대상을 환원한다.

새 주제에서는 `buildScene()`의 다리를 핵심 대상, `makeHouse()`의 양쪽 집을 보조 대상, `makeTree()`를 주변 맥락으로 바꾼다. 넓은 하늘에는 해와 구름 4개, 지면에는 `makeMeadow()`의 풀·돌·꽃과 `makeFence()`의 울타리를 분산한다. 디테일 선은 `line()`의 8px만 사용하며 모든 오브젝트에 테두리를 두르지 않는다.

## Material — 재질

`MATERIAL`과 `rect()`·`circle()`·`path()`는 단색 기하 도형만 만든다. 빛 반사나 거칠기 대신 크기·면적·간격으로 재료의 성격을 드러낸다. 창틀은 사각 면의 조합, 나무는 원형 활엽수와 삼각형 침엽수로 구분한다. 새 제품이나 인물도 사진 질감을 붙이지 말고 같은 도형 어휘로 단순화한다.

## Lighting — 조명

`LIGHTING`의 결정은 그림자·그라데이션 없음이다. 별도 광원이나 접촉 그림자를 추가하지 않는다. 지면에 고정된 나무 밑동, 집의 기단, 다리의 양 끝으로 접지를 읽게 한다. 해는 광원 계산이 없는 그래픽 요소이며 작은 회전만 한다.

## Camera — 시점과 움직임

`CAMERA`의 중심은 다리 근처 `(960, 640)`, 최대 줌은 1.05다. `render(t)`의 코사인 곡선으로 5초 동안 한 번 들어갔다 돌아오며 속도도 양 끝에서 0이다. 모든 레이어를 같은 비율로 확대한다. 정면 2D에서 입체 원근이나 레이어별 패럴랙스를 넣지 않는다.

`spring()`은 준비 동작 → 신장 → 반동 → 작은 반동 → 안착의 키를 `smooth()`로 잇는다. 나무는 밑동을 축으로 크기와 회전을 바꿔 땅에서 뜨지 않는다. `TREES`의 순서별 위상차가 탄성을 전달한다. 구름은 느린 왕복, 물결은 192px 간격의 순환, 연기는 커짐·상승·투명도로 소멸한다. 자동차도 5초 안에 왕복한다. 모든 값은 현재 `t`만으로 계산한다.

## Rendering — 실행과 내보내기

`index.html`은 `viewBox="0 0 1920 1080"`을 유지하며 화면 비율에 맞춰 크림색 레터박스를 만든다. SVG는 해상도 독립적이므로 Canvas의 DPR 설정이나 Three.js가 필요 없다. 유일한 가져오기는 `../../shared/runtime.js`이며 외부 에셋·폰트·네트워크를 사용하지 않는다.

실시간 재생은 공통 `start(render)`의 시계와 브라우저의 SVG 안티앨리어싱을 사용한다. URL의 `?t=2.5`는 같은 화면을 고정하며 `window.__demo.seek(t)`로 임의 시점을 재현한다. MP4 오프라인 렌더링은 모션 설정을 바꾸지 않고 1920×1080에서 `t = 프레임번호 / fps`를 지정한다. 30fps는 0~149, 60fps는 0~299 프레임만 출력해 5초의 중복 끝 프레임을 제외한다. 더 높은 해상도는 브라우저 캡처 크기만 바꾸고, 인코딩은 고품질 H.264와 yuv420p를 사용한다. 실제 MP4 인코딩과 프리뷰 생성은 이 데모의 작업 범위 밖이다.

## QA — 재현과 금지 효과

`render()` 호출 순서를 바꿔도 같은 시간에는 같은 속성이 나와야 한다. `spring(0)`과 `spring(1)`의 일치, 나무 8그루, 7색 팔레트와 5초 길이는 코드의 자체 검사로 확인한다. 브라우저에서는 0·2.5·4.9초 및 4.999→0초, 창 크기 변경, 오류와 외부 요청을 검사한다. 나무의 밑동·집의 기단·다리 접지, 아치 개구부, 난간과 차량의 겹침을 우선 확인한다.

DOF, 블러, 그라데이션, 텍스처, 사실적 그림자, 원근 투영, 글로우, CSS animation/transition, 누적 시뮬레이션과 별도 시계를 사용하지 않는다. 부드러움은 후처리가 아니라 주기 함수와 가감속에서 만든다.

### 이번 구현의 검증 기록

Chrome 헤드리스에서 1920×1080의 0·2.5·4.9초 화면을 4차례 렌더링하고 직접 확인했다. 첫 확인 후 강과 교각 접지·물결의 순환 경계를, 두 번째 확인 후 덤불과 나무 간격을, 세 번째 확인 후 창문·문과 전경 디테일의 겹침을 개선했다. 1000×800 창에서도 16:9 레터박스와 스크롤 없는 배치를 확인했다.

`node --input-type=module --check`, 자동 재생, 시간 호출 순서 독립성, 0초와 5초의 SVG 속성 일치, 탄성 함수 1,001개 입력, 나무 8그루·구름 4개·7색 팔레트 검사에 통과했다. 브라우저 오류·실패 응답·외부 요청·CSS 애니메이션은 모두 0건이었다. 4.999초와 0초 이미지의 평균 채널 차이는 255 기준 약 0.003으로 측정했다. 임시 캡처와 검증 스크립트는 OS 임시 폴더에만 저장했다. 다른 브라우저와 실제 MP4 인코딩은 확인하지 않았다.
