# 아이소메트릭 재사용 가이드

실행 파일은 `index.html`, 구현은 `demo.js`다. 스킬 루트를 정적 서버로 열고 `/styles/01-isometric/`에 접속한다. 로컬 `vendor/three/build/three.module.min.js`와 `shared/runtime.js`만 가져오므로 인터넷 연결이 필요 없다. `file://` 대신 HTTP를 사용한다.

## Art — 형태·색·배치

`PALETTE`의 민트·청록·코랄·스카이블루·크림·흙색·짙은 녹색을 중심으로 밝고 어두운 파생색을 사용한다. 화면 중앙의 밝은 다리, 그 뒤 좌우의 지붕 두 색, 앞쪽의 낮은 식생 순서로 시선을 정리했다. 흙 단면 4층과 잔디층이 사각 타일의 두께를 드러낸다. 강은 화면 왼쪽 뒤에서 오른쪽 앞으로 흐른다.

`buildTerrain()`은 굽은 수로와 양쪽 땅을 별도 프리즘으로 만든다. `riverCenter()`와 `bank()`로 강 경로를 정한다. `buildBridge()`는 18개 아치 구간과 양옆 난간을 생성한다. `buildHouse()`·`windowFrame()`은 지붕, 문, 창틀, 화분을 재사용한다. `buildTree()`는 활엽수와 침엽수를 만들며 현재 7그루다. `buildDetails()`는 길·울타리·텃밭·벤치·돌·갈대를 보완한다. 기본 조형은 `box()`·`prism()`·`stone()`·`beam()`이다.

새 주제에서는 집을 학교·작업장·시설로 바꾸고 강과 다리를 흐름·연결의 비유로 사용할 수 있다. 작은 주제를 많이 나열하기보다 초점 하나와 보조 시설 두 개의 위계를 유지한다. 객체를 추가할 때는 둔덕과 물 높이, 집 출입구와 오솔길 접속, 나무 수관과 지붕 사이의 실제 거리를 확인한다. 언덕은 타일 뒤쪽에 낮게 두고 나무 밑동과 겹치지 않는다.

## Material — 무광 표면

`MATERIAL`과 캐시 함수 `matte()`를 사용한다. 모든 일반 표면은 `MeshStandardMaterial`, roughness 1, metalness 0, flatShading이다. 법선과 조명으로 위·좌·우 면의 밝기를 나누며 외부 텍스처, 노멀맵, 환경맵은 없다. `stone()`은 낮게 눌린 다면체이므로 바닥에 일부 묻어 놓아 접촉면을 확보한다.

연기만 개별 투명 재질을 사용한다. 연기는 `depthWrite: false`로 투명 조각의 깊이 가림을 줄인다. 물은 투명·반사 재질 대신 단색 표면과 흰 기하 줄무늬로 읽힌다. 새 색을 넣을 때는 원색을 추가하기보다 기존 색 계열의 명도 변화를 먼저 사용한다.

## Lighting — 면 구분과 접촉

`LIGHTING`은 방향광 위치·색·세기, 반구광 색·세기, 그림자 해상도와 보정값을 모은다. 방향광 1개와 반구광 1개를 쓴다. 4096 그림자 맵의 `PCFSoftShadowMap`, bias -0.00015, normalBias 0.035로 접촉과 면 구분을 확보했다. 일반 메시의 `castShadow`·`receiveShadow` 기본값은 둘 다 참이다. 물결·연기·구름은 투영 그림자를 만들지 않는다.

새 주제로 타일 크기를 바꾸면 `shadowExtent`와 그림자 카메라의 far 범위를 함께 조절한다. 그림자 범위만 과하게 넓히면 접촉부 해상도가 떨어진다. 물결은 수면 위 0.064단위에 두어 수면의 그림자를 받으면서 깊이 충돌을 피한다. 햇빛을 지나치게 높이면 톤매핑 없는 파스텔 면이 하얗게 뭉개진다.

## Camera — 평행선이 유지되는 시점

`CAMERA`의 yaw는 π/4, pitch는 atan(1/√2)로 고정한다. `OrthographicCamera`의 투영 높이는 16.8이고 화면 비율은 16:9다. `render(t)`는 카메라의 회전을 바꾸지 않고 위치만 평행 이동한다. `(1-cos(2πt/5))/2`로 한 번의 줌인·줌아웃과 팬 왕복을 만들어 시작·끝 속도가 모두 0이다. 최대 줌은 1.045다. 섬은 0.045단위로 가볍게 부유한다.

새로운 시설을 배치할 때는 높이부터 확인한다. 카메라 회전이나 원근 투영으로 구도를 맞추지 말고 `CAMERA.height`·`targetY`와 시설 좌표를 조절한다. 최대 줌 시점인 2.5초에 구름과 타일 하단이 안전 여백 안에 있어야 한다.

## Rendering — 실시간과 MP4

`RENDERING`과 `resize()`가 antialias 및 DPR 상한 2를 적용한다. 출력은 `SRGBColorSpace`, 톤매핑은 `NoToneMapping`이다. 투명 WebGL 캔버스 아래 HTML의 연한 하늘색→크림색 그라데이션이 보인다. 화면 밖 여백도 같은 계열이다. CSS 애니메이션, GSAP, 자체 재생 시계, 누적 위치값, 비결정적 난수는 사용하지 않는다.

| 설정 | 실시간 재생 | MP4 오프라인 렌더링 |
| --- | --- | --- |
| 시계 | `start(render)`가 자동 재생 | `?t=0`으로 정지 후 `window.__demo.seek(n/fps)` |
| 프레임 수 | 디스플레이 주사율을 따름 | 60fps라면 n=0…299, 정확히 300장; 마지막에 5초 프레임을 중복하지 않음 |
| 출력 크기 | 창 크기에 맞춰 16:9, DPR 최대 2 | 브라우저 뷰포트 1920×1080, DPR 1로 정확한 1920×1080 캡처 |
| 품질 | 4096 그림자, AA 활성화 | 동일하게 유지; 더 높은 해상도는 뷰포트 크기를 먼저 늘림 |
| 배경 | CSS 그라데이션 포함 | 페이지 전체를 캡처해 CSS 배경을 합성; 캔버스만 추출하면 투명 배경이 됨 |
| 색 | sRGB, 톤매핑 없음 | 동일한 sRGB 프레임을 인코딩하고 전달용 영상은 BT.709 색 정보를 확인 |

`render(t)`는 호출 순서와 무관하게 모든 동적 속성을 다시 지정한다. `buildAtmosphere()`의 물결과 폭포, `buildHouse()`의 연기, `buildTree()`의 바람은 정수 주기로 반복한다. `saw()`의 경계에서는 물결 길이·폭포 길이·연기 투명도를 0으로 만들고 `smooth()`로 이동을 가감속한다. 임의 시점을 요청한 직후 캡처할 수 있다. 브라우저 캡처에서는 `window.__demoReady`를 먼저 기다린다.

사용하지 않는 효과는 피사계 심도, 원근 투영, 회전 궤도, 사실적 반사, 블룸, 모션 블러, 그레인이다. 시설과 창틀을 선명하게 비교하는 견본이므로 흐림이나 하이라이트로 형태를 가리지 않는다. 재질의 roughness를 낮추거나 HDR 환경맵을 더하면 다른 스타일이 된다.

## QA — 실제 화면 검증

로컬 Chrome을 `playwright-core`의 `chromium.launch({ channel: 'chrome' })`와 `--ignore-gpu-blocklist --enable-gpu --use-angle=d3d11`로 실행한다. 정적 서버는 스킬 루트에서 `python -m http.server <빈 포트>`로 실행하고 검증 후 종료한다. 캡처와 검증 스크립트는 OS 임시 폴더에 둔다. `preview.png`·`preview.gif`는 이 구현에서 만들지 않는다.

검증 기준은 1920×1080의 t=0, 2.5, 4.9 직접 확인, 0초와 5초 이미지 완전 일치, 임의 시점 재방문 이미지 일치, 4.999초와 0초의 근접성이다. 리사이즈에서는 16:9 중앙 정렬과 스크롤바 유무를 확인한다. 외부 네트워크 요청·페이지 오류·실패한 모듈 요청은 모두 0건이어야 한다. 정사영 축 비율과 고정 회전, 나무 수 7개, 로컬 import 파일 존재, 모듈 문법을 함께 검사한다.

첫 검토에서 구름의 상단 잘림, 언덕과 나무 겹침, 과한 조명 밝기를 수정했다. 두 번째 검토에서는 최대 줌 구름 여백, 텃밭과 밑동 간격, 물결 분포를 다듬었다. MP4 파일 자체의 인코딩과 다른 GPU·휴대기기의 재생 성능은 별도 검증 대상이다.
