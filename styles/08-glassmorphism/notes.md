# 글래스모피즘 / 시네마틱 UI 재사용 안내

## 새 주제에 적용하기

`index.html`의 설명·수치·지시 칩을 새 주제의 정보로 바꾸고, `demo.js`의 배경 그리기 함수를 교체한다. 풍경은 색과 밝기가 충분히 달라야 움직이는 유리 뒤에서 실제 블러가 드러난다. 주요 대상은 중앙, 큰 설명은 왼쪽 위, 보조 수치는 오른쪽 위와 아래에 둔다. 지시 칩은 `updateChip()`의 대상 좌표를 바꾸어 연결한다. 대상의 지붕·다리 난간을 카드가 덮지 않는지 세 시점에서 확인한다.

새 패키지나 빌드 과정 없이 스킬 루트의 정적 서버에서 `styles/08-glassmorphism/`을 연다. 공통 시계는 `../../shared/runtime.js`만 가져온다. Three.js를 사용하지 않으므로 `vendor/three/`에 대한 import는 없다.

## Art · 형태와 밀도

- 팔레트: `PALETTE`의 남보라·인디고·자주·장미·살구·회녹·상아. 지붕과 조명은 이 색의 명도 변주로 맞춘다.
- 원경은 4개의 얇은 구름과 산 2겹, 중경은 강·아치 다리·두 집·나무 6그루, 전경은 나무 2그루와 갈대·돌·덤불·울타리다. 총 나무는 8그루다.
- 재사용: `drawSky()`, `drawGround()`, `drawHouse()`, `drawTree()`, `drawShrub()`, `drawFence()`, `drawForeground()`. 집은 `blue` 인자로 지붕색과 굴뚝 유무를 바꾼다.
- 새 대상의 바닥은 같은 좌표계에 놓고 타원 접촉 그림자를 붙인다. `drawBridge()`와 `bridgeTop()`의 난간·등불은 같은 상단 곡선을 기준으로 정렬한다.

## Material · 유리와 물

- `MATERIAL`은 주요 유리 블러 32px, 채도 1.65와 수면 선의 불투명도, 다리 석재색을 모은다. `index.html`의 `.glass`가 흰 틴트 0.10~0.18, 비대칭 그라데이션 테두리, 상단 반사광과 부드러운 그림자를 만든다.
- `.surface`만 잘라서 이동 반사 띠를 담는다. 상위 요소의 `opacity`나 `filter`로 별도 합성 경계를 만들면 실제 배경 블러가 사라질 수 있으므로 카드 전체에는 적용하지 않는다.
- 지시 칩은 작은 면적에 맞춰 blur 25px, saturate 1.5다. 표면 반사광은 `render()`의 `sheens` 계산으로 각 패널마다 5초에 한 번 지나간다.
- `drawWater()`는 강 모양으로 클리핑한 그라데이션, 가는 빛 조각, 창문 반사를 사용한다. 실제로 매 프레임 움직이는 Canvas를 DOM이 직접 흐린다. 배경 스크린샷을 유리 안에 복제하지 않는다.

## Lighting · 명암과 접지

- `LIGHTING`에서 낮은 태양의 위치·크기, 창문색, 비네트 강도를 조정한다. `halo()`는 별도 텍스처 없이 작은 국소 대기광을 만든다.
- 창문은 문틀·십자 창살·창턱까지 그린다. 밝은 면적을 작게 유지해 다리 양끝 등불과 연결한다. 나무·집·덤불·돌의 타원 그림자와 다리 받침의 어두운 띠가 지면 접촉을 표현한다.
- 텍스트는 흰색 계열과 어두운 그림자로 처리한다. 모든 본문·보조 문구는 1920 논리 화면 기준 22px 이상이다.

## Camera · 구성과 움직임

- `CAMERA`의 1920×1080, zoom 1.035, panX 24, panY -8을 시작점으로 쓴다. `cameraOffset()`은 `(1-cos(2πt/5))/2`로 한 번 왕복하며 출발·도착 속도가 0이다.
- `drawSky()`는 원경을 느리게, `drawScene()`은 중·전경을 같은 투영으로 움직인다. `worldPoint()`와 `updateChip()`이 확대·이동 후 대상 좌표에 지시점을 붙인다.
- 나무·입자·파형·패널은 정수 주기의 삼각함수만 쓴다. 연기는 고정 간격 위상의 입자가 수명 양끝에서 완전히 사라져 되돌림을 감춘다. 난수는 고정 시드로 로드할 때 한 번만 생성한다.
- 진행 막대의 길이는 정확히 `t/5`다. 채움 선만 경계 양쪽 0.35초 동안 부드럽게 숨겨 100%→0% 리셋을 감춘다. 시간 문구·트랙·카드·제목은 계속 보인다.

## Rendering · 실시간과 MP4

- 실시간: `resize()`가 논리 스테이지를 CSS transform으로 창에 맞추며 Canvas DPR은 최대 2다. 공통 `start(render)`가 자동 재생·정지·탐색을 담당한다. 네트워크·웹폰트·이미지·3D 의존성은 없다.
- MP4 오프라인: Chrome에서 1920×1080 뷰포트, 고정 deviceScaleFactor 1 또는 2를 설정한다. `?t=0`으로 열고 `window.__demoReady`를 기다린 뒤 `window.__demo.seek(frame / fps)` 후 브라우저 합성이 끝난 화면 전체를 캡처한다. Canvas만 내보내면 DOM 유리가 빠진다.
- 30fps는 150장, 60fps는 300장을 캡처한다. 마지막 프레임은 각각 149/30 또는 299/60초이며 5초 프레임을 중복 추가하지 않는다. 스타일 값이나 모션 속도는 오프라인에서도 바꾸지 않는다. DPR 2는 더 선명하지만 캡처 부하가 커진다.
- 인코딩은 원본 크기·고정 프레임률로 수행한다. MP4의 4:2:0 색 변환에서는 가는 따뜻한 테두리가 약해질 수 있으므로 최종 파일에서 확인한다. 이 산출물에는 인코더나 MP4를 포함하지 않는다.

## QA · 직접 검증할 기준

- `node --input-type=module --check`로 `demo.js`를 확인하고 공통 import의 실제 파일 존재를 확인한다.
- Chrome 헤드리스로 1920×1080의 t=0, 2.5, 4.9를 캡처한다. 다리 밑 빈 공간·집 지붕·지면 접촉·화면 밀도·테두리 AA·한국어 글자 잘림을 눈으로 확인한다.
- t=0을 그린 뒤 다른 시간을 탐색하고 다시 t=0으로 돌아온 화면이 같은지 확인한다. 4.999와 0은 막대 리셋까지 감춰져야 한다.
- 실제 CSS backdrop-filter를 비활성화한 비교 화면과 정상 화면의 패널 영역을 비교한다. 960×540으로 축소한 상태에서도 이 차이가 유지돼야 한다. deviceScaleFactor 2와 작은 창 리사이즈도 확인한다.
- 금지: 불투명 패널, 무의미한 장식 카드, 과한 네온 글로우, 색수차, 필름 그레인, 모션 블러, CSS animation/transition, 누적 시뮬레이션, 외부 네트워크 요청.
